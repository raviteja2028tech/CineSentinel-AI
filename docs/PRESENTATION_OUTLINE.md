### Slide 2 — Problem statement and objectives
- Problem: decide whether an IMDb review is positive or negative
  (document-level binary classification)
- Reference: Wu & Shin (Stanford CS229) compare six classifier families
- Objectives: reproducible pipeline; six classifiers on identical features;
  standard metrics on the official test split; interactive app
- *Say:* the question is not only which model is most accurate, but what
  that accuracy costs in training time.

### Slide 3 — Dataset and preprocessing
- Stanford Large Movie Review Dataset: 50,000 reviews, 25k / 25k official
  split, 50% / 50% classes, median 174 words
- Official split unchanged; test split used only for final evaluation
- 123 test reviews (0.49%) also occur in train — disclosed, left in place
- Content verified identical to the official Stanford archive
- Cleaning: strip HTML → lowercase → remove punctuation, digits, stop
  words → lemmatize
- Features: TF-IDF, unigrams + bigrams, 50,000 terms, fitted on train only

### Slide 4 — Methodology and system architecture
- Offline: dataset → cleaning → TF-IDF → training → evaluation
- Online: saved files → inference → Streamlit dashboard (5 pages)
- One feature matrix for all six models, so the comparison is like-for-like
- Model selection uses training data only; test split evaluated once
- No GPU, no paid API

### Slide 5 — Six machine-learning classifiers
| Model | Family | Key settings |
|---|---|---|
| Logistic Regression | Linear | L2; C by 3-fold CV → 1 |
| Linear SVM | Linear | L2; C by 3-fold CV → 0.25; Platt-calibrated |
| Multinomial Naive Bayes | Probabilistic | Laplace smoothing = 1 |
| Random Forest | Tree ensemble | 100 trees, Gini, no depth limit |
| Gradient Boosting | Tree ensemble | 270 trees (validation-selected), learning rate 0.1 |
| Neural network (MLPClassifier) | Neural network | layers (30, 30, 20, 10, 10), Adam, early stopping |
- *Say:* settings are the paper's, except the boosting tree count. With
  the paper's 100 trees it scored 81.1%; we investigated, found it was
  underfitting rather than a bug, and chose 270 on validation data.

### Slide 8 — Conclusion, limitations and future scope
- Conclusion: all six implemented and evaluated; linear models and the
  neural network reach about 89%; a linear model gives the best balance of
  accuracy, training time and interpretability
- Limitations: not an exact reproduction (1–2-grams, not 3-grams); one run
  per model; bag-of-words ignores word order
- Future scope: repeated seeds; further tuning of tree ensembles; binary
  and count features for all six models; sequence models

## Questions to be ready for

- **Why is your Gradient Boosting number different from the paper's
  setting?** 100 trees underfit 50,000 sparse features. A shuffled-label
  control scored chance, ruling out a bug. The count was chosen on
  validation data; both test results (81.07% and 84.41%) are reported.
- **Did you tune on the test set?** No. C by cross-validation, early
  stopping on a training hold-out, tree count on a validation split.
- **Is the SVM "confidence" a probability?** It is a Platt-calibrated
  probability, not the raw decision score.
- **Why not binary features, which the paper found best?** A side
  experiment on validation data found TF-IDF best for the three fast
  classifiers, but classifier settings were not re-tuned per
  representation, so it is not conclusive.
- **Is the dataset the real one?** Yes: all 50,000 review–label pairs
  match the official Stanford archive.
